# log-tech-debt

Capture a tech debt item as a GitHub issue and move on. No grilling, no triage
— just log it.

This skill requires interactive use — a human must confirm before the issue is
created.

## Invocation

```
/log-tech-debt "the auth middleware stores tokens in plaintext"
/log-tech-debt                              # synthesize from conversation
/log-tech-debt --repo owner/other-repo "legacy CSV parser needs replacing"
```

## Process

### 1. Gather the idea

- **If args contain a description:** use it as the idea.
- **If no args (or only `--repo`):** synthesize from the current conversation
  context. Identify the shortcut, outdated pattern, or scaling concern that
  prompted the capture.

### 2. Inspect the code area (optional)

If the conversation or args reference specific code, briefly inspect the
relevant files to enrich the issue with concrete details:

- File paths and line numbers
- Current state of the code (what the debt looks like today)
- Why it's debt (what's wrong with the current approach)

Keep inspection lightweight — read a few files, don't deep-dive. The goal is
enough context to act on later, not a full analysis.

### 3. Draft the issue

Write a short title (under 80 chars) and a body using this template:

```markdown
## Debt

<1-2 sentence description of the shortcut, outdated pattern, or concern>

## Motivation

<Why this matters — what risk, maintenance burden, or scaling concern does it create?>

## Context

<What conversation, task, or observation surfaced this debt? Include file paths and current state if inspected.>

> *This issue was generated by AI.*
```

Target repo: use `--repo` if provided, otherwise the current git repo.

### 4. Check for duplicates

Search existing tech-debt issues for potential duplicates:

```bash
gh issue list --label tech-debt --state all --search "<keywords from title>" --json number,title,state
```

Extract 2-3 keywords from your drafted title for the search.

### 5. Confirm with the user

Present everything in one step:

**If duplicates found:**

```
## Potential duplicates

- #42: "Auth middleware stores tokens in plaintext" (open)
- #17: "Session storage needs encryption" (closed)

## Draft issue

**Repo:** owner/repo
**Title:** Auth middleware uses plaintext token storage
**Labels:** tech-debt

<full body preview>

Create this issue? (yes / edit / cancel)
```

**If no duplicates:**

```
## Draft issue

**Repo:** owner/repo
**Title:** Auth middleware uses plaintext token storage
**Labels:** tech-debt

<full body preview>

No duplicate tech-debt issues found.

Create this issue? (yes / edit / cancel)
```

Wait for the user's response:
- **yes** — create the issue
- **edit** — ask what to change, revise, re-confirm
- **cancel** — abort, acknowledge

### 6. Create the issue

```bash
gh issue create \
  --repo <repo> \
  --title "<title>" \
  --label tech-debt \
  --body "<body>"
```

If the `tech-debt` label doesn't exist on the target repo, create it first:

```bash
gh label create tech-debt --description "Known shortcuts, outdated patterns, scaling concerns" --color "D93F0B" --force
```

### 7. Report

Return the issue URL. One line. Done.
