# log-wishlist

Capture a wishlist idea as a GitHub issue and move on. No grilling, no triage
— just log it.

This skill requires interactive use — a human must confirm before the issue is
created.

## Invocation

```
/log-wishlist "offline mode for the app"
/log-wishlist                              # synthesize from conversation
/log-wishlist --repo owner/other-repo "idea here"
```

## Process

### 1. Gather the idea

- **If args contain a description:** use it as the idea.
- **If no args (or only `--repo`):** synthesize the idea from the current
  conversation context. Identify what the user was discussing that prompted
  the capture.

### 2. Draft the issue

Write a short title (under 80 chars) and a body using this template:

```markdown
## Idea

<1-2 sentence description of the feature or improvement>

## Motivation

<Why this matters — what problem does it solve or what value does it add?>

## Context

<What conversation, task, or observation spawned this idea?>

> *This issue was generated by AI.*
```

Target repo: use `--repo` if provided, otherwise the current git repo.

### 3. Check for duplicates

Search existing wishlist issues for potential duplicates:

```bash
gh issue list --label wishlist --state all --search "<keywords from title>" --json number,title,state
```

Extract 2-3 keywords from your drafted title for the search.

### 4. Confirm with the user

Present everything in one step:

**If duplicates found:**

```
## Potential duplicates

- #42: "Add offline caching" (open)
- #17: "Connectivity fallback" (closed)

## Draft issue

**Repo:** owner/repo
**Title:** Offline mode for mobile app
**Labels:** wishlist

<full body preview>

Create this issue? (yes / edit / cancel)
```

**If no duplicates:**

```
## Draft issue

**Repo:** owner/repo
**Title:** Offline mode for mobile app
**Labels:** wishlist

<full body preview>

No duplicate wishlist issues found.

Create this issue? (yes / edit / cancel)
```

Wait for the user's response:
- **yes** — create the issue
- **edit** — ask what to change, revise, re-confirm
- **cancel** — abort, acknowledge

### 5. Create the issue

```bash
gh issue create \
  --repo <repo> \
  --title "<title>" \
  --label wishlist \
  --body "<body>"
```

If the `wishlist` label doesn't exist on the target repo, create it first:

```bash
gh label create wishlist --description "Feature ideas and future enhancements" --color "0E8A16" --force
```

### 6. Report

Return the issue URL. One line. Done.
